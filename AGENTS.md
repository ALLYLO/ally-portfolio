# Portfolio working rules

1. Read PROJECT_CONTEXT.md first. Read README.md for local preview and publishing. Then read only the context document and source files relevant to the task.
2. Treat this directory as the Portfolio Git scope. Before Git operations, confirm that git rev-parse --show-toplevel resolves to this repository; do not use the enclosing repository for Portfolio work.
3. Use current source to establish what is currently implemented. Use owner-confirmed decisions and evidence-backed content guidance to establish what is confirmed. Source code alone cannot verify business claims.
4. Follow the status definitions in PROJECT_CONTEXT.md. Do not turn a candidate, historical item, or Needs confirmation item into a confirmed fact without the required evidence and owner decision. Do not fill gaps by guessing.
5. Keep tracked context public-safe. Do not add private conversation identifiers, local absolute paths, identity mappings, internal source records, raw evidence, or credentials to this repository.
6. Keep each fact with its owner: README.md for operation and deployment instructions; PROJECT_CONTEXT.md for baseline and context map; CONTENT_GUIDE.md for claim standards; DESIGN_GUIDE.md for approved design constraints; DECISIONS.md for confirmed decisions; OPEN_QUESTIONS.md for unresolved items; TODO.md for tasks.
